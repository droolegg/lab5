# Вакансії — Лабораторна №5 (Захищена адмін-панель)

Окремий проєкт на основі ЛБ-4 (Express + Prisma + Handlebars + Passport.js).
Додано **захищену область `/admin`**, де авторизований користувач з роллю **Адміністратор**
може додавати, редагувати та видаляти дані **всіх таблиць** системи:
категорії, роботодавці, шукачі роботи, вакансії, відгуки, користувачі.

## Запуск

```bash
npm install
npm run setup      # prisma migrate deploy + початкові дані (seed)
npm start          # http://localhost:3000  (адмін-панель: http://localhost:3000/admin)
```

Нових міграцій у цій роботі немає — схема БД та сама, що в ЛБ-4.
Змінна `SESSION_SECRET` (необов'язково) задає секрет для підпису сесійної cookie.

## Тестові облікові записи (після `npm run seed`)

| Роль            | Email                  | Пароль       |
|-----------------|------------------------|--------------|
| Адміністратор   | admin@example.com      | admin123     |
| Роботодавець    | employer@example.com   | employer123  |
| Шукач роботи    | seeker@example.com     | seeker123    |
| Відвідувач      | (без входу)            | —            |

## Захист адмін-панелі

| Хто звертається                    | Результат на `/admin/*`          |
|------------------------------------|----------------------------------|
| Відвідувач (не авторизований)      | **401** + форма входу            |
| Шукач роботи / Роботодавець        | **403** «Доступ заборонено»      |
| Адміністратор                      | повний доступ                    |

Захист задано один раз для всього роутера: `router.use(requireRole('ADMIN'))` (`routes/admin.js`).

## Маршрути адмін-панелі

| Метод  | URL                          | Дія                               |
|--------|------------------------------|-----------------------------------|
| GET    | `/admin`                     | головна: кількість записів у таблицях |
| GET    | `/admin/:resource`           | список (пошук `?q=`, сторінки `?page=`) |
| GET    | `/admin/:resource/new`       | форма додавання                   |
| POST   | `/admin/:resource`           | створення                         |
| GET    | `/admin/:resource/:id/edit`  | форма редагування                 |
| PUT    | `/admin/:resource/:id`       | оновлення                         |
| DELETE | `/admin/:resource/:id`       | видалення                         |

`:resource` — `categories`, `employers`, `jobseekers`, `vacancies`, `applications`, `users`.

## Структура (нове в ЛБ-5)

```
admin/resources.js               ← опис усіх таблиць: поля, колонки списку, правила, спец. логіка
controllers/adminController.js   ← універсальний CRUD (список, створення, редагування, видалення)
validators/adminValidator.js     ← правила express-validator, що будуються з опису полів
routes/admin.js                  ← маршрути + захист requireRole('ADMIN')
views/admin/                     ← dashboard.hbs, list.hbs, form.hbs
views/partials/adminMenu.hbs     ← меню таблиць і flash-повідомлення
```

## Особливості

- Роботодавці й шукачі створюються разом з обліковим записом (User) — як при реєстрації; пароль хешується bcrypt.
  При редагуванні поле «Пароль» необов'язкове (порожнє = не змінювати), email змінювати не можна.
- Валідація на сервері: довжини, формат email/телефону/сайту, унікальність, існування пов'язаних записів,
  зарплата «до» ≥ «від», відповідність ролі користувача його профілю.
- Захист від помилок: не можна видалити власний обліковий запис і зняти з себе роль адміністратора;
  категорію з вакансіями видалити не можна (повідомлення замість помилки); видалення потребує підтвердження.
- Каскадне видалення: роботодавець → його вакансії та відгуки; шукач → його відгуки; вакансія → її відгуки.
